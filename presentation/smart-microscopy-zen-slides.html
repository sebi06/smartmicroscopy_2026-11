ZEN-API / architecture

Your application decides. ZEN executes acquisition.

Typed services, not mouse clicks. The gateway shares access and service descriptions; providers register capabilities. Complements OAD, not every internal function.

ZEN-API / contracts

A typed contract connects different languages.

gRPC uses HTTP/2. A contract is not a microscope driver; generated client code cannot add unsupported server features.

ZEN-API / Python layers

Generated contracts and workflow helpers have different jobs.

The client stack

  • zen_api: generated messages and gRPC wrappers.
  • zen_api_utils: separate connection and workflow helpers.
  • NumPy, AI, and visualization: client-side choices.

Match the running system

  • Package version is not a service namespace.
  • v1 and v1beta can coexist.
  • Methods depend on server, edition, and instrument.

Newer reviewed contracts do not imply ZEN 3.14 support.

ZEN-API / receiving pixels

Choose delivery and manage processing lag.

  • GetNextFrame: one response, with experiment/channel scope.
  • MonitorExperiment / MonitorAllExperiments: server streams.
  • enable_raw_data: raw lines or partial frames; otherwise assembled frames.
  • Separate reception, analysis, and hardware decisions.
  • Bound buffers; measure lag; define overload behavior.

These are engineering choices, not a hard real-time guarantee.

napari / operating modes

Watch, start, or store an acquisition.

  • Watch: ZEN starts; napari listens. Run only one acquisition.
  • Start: read experiment XML; filter by the returned experiment ID.
  • OME-Zarr only: dedicated channel and writer; start or arm before manual acquisition.

Connecting alone does not start acquisition.

napari / display versus storage

Preview values are not raw measurement values.

  • Display normalizes assumed uint16 frames.
  • Received frames remain available for scene mosaics.
  • Small live previews do not mean constant memory.
  • The direct writer preserves GRAY8 / GRAY16; not color.

napari / operating limits

Check completeness and compatibility separately.

Did all frames arrive?

  • Final pixels may follow acquisition-finished status.
  • Started Display runs check unique frame count, with inactivity fallback.
  • The configured writer checks coordinates; inspect acquisition_status.json.
  • Older unconfigured CLI lacks equivalent certification.

Does this setup match?

  • Alpha / MVP; primarily ZEN Blue on Windows.
  • Python 3.12-3.14; API 2026.5.1-2026.11.1.
  • Install compatible API and utility wheels in napari's environment.
  • Remote Linux streaming is experimental, not hardware-certified.
